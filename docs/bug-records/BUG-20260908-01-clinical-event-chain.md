# BUG-20260908-01：挂号、检查报告和处方提醒链路关联错误

## 现象

- 已有眼科排班时，AI 挂号仍提示科室不存在。
- 检查结果推送找不到患者，血糖报告可能读取到旧的鼻窦 CT 内容。
- 医生开方后，患者收不到取药地点和定时用药提醒。
- 检查项目页面无法新增项目，处方关联字段容易选错。

## 根因

1. 系统排班精确查询为空后，AI 降级使用另一套科室表，两套科室数据不一致。
2. 报告事件调用 ReportAgent 时使用固定 `default` 会话，且事件没有传递完整指标或影像所见。
3. RabbitMQ 在工作线程中创建临时事件循环，处理完成后关闭，后续提醒任务随之失效；WebSocket 发送也跨越了所属事件循环。
4. 前端聊天连接和后端患者通知使用不同频道；患者列表响应只兼容一种包装格式。
5. 检查结果的患者 ID 由前端提交，后端没有根据检查申请单重新确认。
6. 检查项目页面的新增按钮被注释，新增表单也缺少默认值和必填校验。

## 修复

- 排班查询显式连接 `ruoyi-system:9201`，精确查询为空时对科室、日期和时段做规范化匹配。
- 报告解读使用“患者 ID + 报告 ID”作为隔离会话，并传递完整数值指标、影像所见和结论。
- 报告生成后先询问患者是否需要分析，解读结果按患者缓存，患者确认后再展示。
- WebSocket 跨线程发送回到 Uvicorn 主事件循环；提醒任务固定在主事件循环运行。
- 检查结果服务以检查申请单为准回填患者和挂号 ID。
- 前端患者选择后订阅 `patient:{patientId}` 会话，兼容不同列表响应包装并显示加载失败原因。
- 恢复检查项目新增入口，补齐默认值和表单校验；开处方时锁定当前挂号的患者、科室和医生。

## 验证

- `ylxm-reghos` Maven reactor 编译通过。
- Vue development build 编译通过。
- 修改文件通过 `git diff --check`。
- 当前 Codex 进程找不到系统 Python，项目虚拟环境又指向已不存在的基础解释器，因此未在该进程中执行 Python 编译；需在 IDEA 已配置的 Python 3.12 解释器中启动服务完成运行验证。

## 回归步骤

1. 选择测试患者后确认 AI WebSocket 会话为 `patient:{patientId}`。
2. 查询眼科指定日期和时段，选择 yan 并完成挂号。
3. 新增或选择血糖项目开检查单，录入数值报告。
4. 患者应收到“检查结果已经出来，是否需要分析”，回复“帮我分析报告”后只展示本次血糖结果。
5. 医生开药后，患者应立即收到取药地点和用药规则，并在配置的测试间隔后收到用药提醒。
