# 本地基础设施连接配置

## 背景

项目原先连接 Rocky Linux 虚拟机中的 MySQL、Redis、MongoDB 和 RabbitMQ。开发环境现已迁移到 Windows 本机服务，统一通过 `127.0.0.1` 访问。

## 配置分层

- Nacos `dev` 命名空间的 `datasource.yml` 保存各 Java 业务模块的 MySQL 数据源。
- Nacos `application-common.yml` 保存 Java 微服务共享的 Redis 和 RabbitMQ 配置。
- 网关的 `bootstrap.yml` 在连接 Nacos 前就需要 Redis，因此保留本地 Redis 配置。
- `ylxm-customer` 和 `ylxm-reghos` 的 `application.yml` 保存 RabbitMQ 连接配置。
- AI 服务通过 `.env` 读取 MongoDB、Redis 和 RabbitMQ 连接；`app/utils/config.py` 中的值仅作为未加载 `.env` 时的默认值。

## 修改后的本地服务

| 服务 | 地址 | 认证 |
|------|------|------|
| MySQL | `127.0.0.1:3306` | 从本地环境或 Nacos 配置读取 |
| Redis | `127.0.0.1:6379` | 从本地环境或 Nacos 配置读取 |
| MongoDB | `127.0.0.1:27017` | 从本地 `.env` 读取，认证库按本机配置 |
| RabbitMQ | `127.0.0.1:5672` | 从本地环境或 Nacos 配置读取 |
| Nacos | `127.0.0.1:8848` | `dev` 命名空间 |

本机 MySQL 初始为空，已使用 `doc/sql` 中的脚本初始化 `ry_cloud`、`ry_job`、`patient` 和 `treatment`。Nacos 还保留了 `auth` 数据源定义，但仓库没有该库的 SQL 且当前代码未发现直接引用，因此只创建了空的 `auth` 库。虚拟机 MySQL 当前拒绝连接，本次初始化不包含虚拟机中后来产生的业务数据。

## 生效方式

Nacos 配置发布后会通知正在运行的服务，但数据库连接池和消息连接的切换不应依赖热刷新。修改完成后依次重启网关、认证、系统、患者、挂号和 AI 服务，确保所有连接均使用本机配置。

## 验证方法

1. 在 Nacos `dev` 命名空间确认 `datasource.yml` 和 `application-common.yml` 已更新。
2. 启动各 Java 服务，确认日志中没有 MySQL、Redis 或 RabbitMQ 连接异常。
3. 启动 AI 服务，确认 MongoDB 初始化成功、5 个 RabbitMQ 队列消费者启动成功。
4. 登录前端并执行患者建档、排班、挂号、检查、报告和开药链路。
