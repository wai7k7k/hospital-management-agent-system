# 学习记录 - 2026-06-08

## 今日涉及的技术点

### 技术点 1: Nginx 反向代理 SSE 流式传输

**是什么**：Nginx 作为反向代理时，默认会缓冲后端响应，导致 SSE (Server-Sent Events) 流式数据被缓冲而非实时推送。

**关键配置**：
```nginx
proxy_buffering off;      # 关闭缓冲
proxy_cache off;           # 关闭缓存
proxy_read_timeout 300s;   # 延长读超时（默认 60s）
```

**用在哪里**：`docker/nginx/conf/nginx.conf` 的 `/api/ai/` location 块。

### 技术点 2: Nginx proxy_pass 尾部斜杠的行为

**是什么**：`proxy_pass` URL 是否带尾部 `/` 决定了 Nginx 是否会剥离匹配的 location 前缀。

- `proxy_pass http://127.0.0.1:8000/`（带 `/`）→ 剥离 `/api/ai/` 前缀
- `proxy_pass http://127.0.0.1:8000`（不带 `/`）→ 保留完整路径

**用在哪里**：同上 location 块。请求 `/api/ai/v1/chat/stream` → 后端收到 `/v1/chat/stream`。

### 技术点 3: LangGraph 工作流不会导致消息重复

**是什么**：审查了 `nodes.py` 的完整工作流代码——每个节点处理一次消息，`chat.py` 只保存一次 user 和 assistant 消息，不存在后端重复处理逻辑。

## 踩到的坑

* **SSE 404 → 降级 HTTP → 前端重试循环**
  * 现象：F12 看到反复 `SSE stream failed, falling back to HTTP: HTTP 404`
  * 原因：Nginx 没有 `/api/ai/` 路由
  * 解决：新增 Nginx location 块
